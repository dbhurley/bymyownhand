### Canonical writing-window derivation + mobile streak visibility + PWA manifest identity (prior revision)

### Canonical-trace metric derivation (read + write boundary) + site-URL trailing-slash hygiene (prior revision)
- ✅ **`/verify/<hash>` derives its metrics from the keystroke trace, not the client `metrics` blob** — the PRD repeatedly states the trace is the canonical record and the score is derived from it *at read time*, but the public proof surface was reading the stored `keystrokeData.metrics` directly and feeding it into `calculateIntegrityScore()`. That blob is client-origin (packaged by `LockedEditor`, round-tripped through the POST body), so a document POSTed straight to `/api/documents` with an honest-looking `events` array next to a hand-crafted `metrics` object (inflated variance, fabricated pauses, zeroed blocked-pastes) would render those fabricated numbers *and* drive the headline integrity score. The page now recomputes `metrics` from the stored `events` + `content` via `calculateMetrics()`, memoized on the document so it runs once per load rather than on every ~10–200ms playback frame (the trace can reach the 250k-event cap). Byte-identical for any editor-minted document (same function the editor used), so pure hardening with no visible change on the legitimate path — and `metrics` is now defined iff a real trace exists, tracking the honest "— / No trace" cells exactly. Read-boundary completion of the §6.10/§6.14/§6.31 "no fabricated evidence" sweep.
- ✅ **`POST /api/documents` persists server-recomputed metrics** — the write-boundary half. The route stored the client `session.metrics` blob verbatim into the `keystroke_data` JSONB column; even with the read-boundary fix making `/verify` ignore it, that stored summary is what a Phase 2.1 API consumer reading `keystroke_data` would get, so it must agree with the events by construction. The route now stores `calculateMetrics(session.events, session.content)`, mirroring the §6.15 server-recompute of `wordCount` (the route already recomputes the count rather than trusting `session.wordCount` for exactly this reason). Runs only on the DB-persist path over an already-bounded trace; identical to the client value for editor-minted documents. The metrics rendered *and* served now both come from the canonical trace.
- ✅ **`getSiteUrl()` collapses all trailing slashes** — the canonical-site-URL helper (single source of truth for every proof link, certificate URL, embed-badge logo, JSON-Feed URL, sitemap entry, and `<link rel="canonical">`) stripped only one trailing slash (`/\/$/`). Since every consumer concatenates `${getSiteUrl()}/…`, a doubled trailing slash in `NEXT_PUBLIC_SITE_URL` (`https://foo.com//`, an easy typo) would leave one behind and emit double-slashed canonical tags, proof links, and feed URLs — a duplicate-URL SEO signal the §6.35 canonical work exists to prevent. Now `/\/+$/` collapses any run. Zero change for a correctly-configured host. `pnpm build` passes; lint unchanged from baseline (the one pre-existing `/success` setState-in-effect error remains deferred).

### Streak-correctness + caching + drift-prevention polish (prior revision)
- ✅ **DST-safe streak day arithmetic in `lib/history.ts`** — the streak walker subtracted a fixed `24 * 60 * 60 * 1000` ms to step a calendar day backward, which goes wrong across DST transitions (a calendar day is 23h or 25h, not 24h). The Phase 1.4 streak counter would have undercounted or overcounted exactly once a year for any writer with an active streak across spring-forward / fall-back. Day arithmetic now goes through a `setDate()`-based `addDays()` helper that moves by one local calendar day — the same unit `dayKey()` compares.
- ✅ **`Cache-Control` on `GET /api/documents/[hash]` for found documents** — a certified document is immutable, but every cold-visitor verify pageload (the embed flywheel target) and every external Phase 2.1 API consumer was round-tripping Neon for the same payload. The route now sets `public, max-age=300, s-maxage=86400, stale-while-revalidate=86400` on found responses so Vercel's edge absorbs the load. 404s remain uncached so a revoked-or-not-yet-created hash never gets stuck.
- ✅ **Single `countWords()` / `splitWords()` helper in `lib/metrics.ts`** — the `content.trim().split(/\s+/).filter(Boolean)` regex was duplicated five times across the editor's live counter, the resume-banner word summary, the API submission gate, the `averageWordLength` calculator, and the metrics path. ## Phase 3 — Hardening the Proof

### 3.1 Tamper-evident hashing
- Sign each certified document with a server-held key.
- Surface a public verification endpoint: given the document content + keystroke trace, recompute the signature and confirm it matches.

### 3.2 Adversarial-replay defense
- Track digraph timings (the rhythm between specific letter pairs) — much harder to script convincingly than average WPM.
- Flag suspiciously regular distributions (low entropy across multiple sessions from the same account).
- Optional opt-in mouse-movement and focus-event capture for stronger signals (clearly disclosed; off by default).

### 3.3 Voice-input / dictation detection
- Detect bursts of perfectly-spelled multi-word inserts inconsistent with character-by-character keystrokes.
- Allow voice-input as an explicit *mode* (with clear labeling on the certificate) rather than silently allowing it to inflate scores.

### 3.4 Optional content-fingerprint check
- Server-side comparison: does the final content reconstruct from the keystroke trace? Mismatches indicate something post-edited the buffer outside our capture path.
